# Первый этап: BASE 8 / 65–35

Файл: `Sniper_Manager_v3_6_5_STAGE1_BASE_65_35.mq5`, база `RESTORED_STOP_FIX` (118cb6e). Изменения касаются новых сделок BASE с комментариями `SMC_B65:<время зоны>` / `SMC_S35:<время зоны>`. EMA, Compression, OTE, отдельный Sweep и AI включены; их правила входа и выхода сохранены. Старые BASE-позиции сохраняют прежний режим сопровождения.

## Зона и ордера

Возвращён прежний детектор: максимум High / минимум Low по 8 завершённым свечам с индексами 2..9, последняя закрытая свеча 1 подтверждает нахождение цены внутри. Прежнее ограничение ширины зоны `< 1.5 ATR` сохранено. В Stop-режиме адаптивное окно 6–24 не используется, даже если старый набор параметров включал `BaseAdaptiveDetection`.

Прямоугольник имеет среднюю горизонтальную линию 50%. При ширине `W = High − Low`:

- Buy Stop = `Low + 0.65 × W`, начальный SL = `Low − BaseInitialSLPips × BasePipSize`.
- Sell Stop = `Low + 0.35 × W`, начальный SL = `High + BaseInitialSLPips × BasePipSize`.
- TP = 0. Наличие H1/H4-экстремума для тейка больше не требуется.

Используются обычные Buy Stop / Sell Stop. Настоящему Stop Limit нужна вторая, отдельно согласованная лимитная цена. Если текущая котировка уже пересекла Stop-уровень, ордер за рынком не выставляется и рыночного догоняющего входа нет. В журнале есть фактические границы, trigger, SL и отказ по расстоянию/риску. Цена округляется наружу к шагу брокера; цены триггеров могут отличаться от математических процентов на один тик.

Встречный собственный BASE-ордер отменяется после исполнения первого, включая частичное исполнение; OCO восстанавливается из истории. Риск, общие лимиты экспозиции, маржа, задержка входа, проверка H4/D1 и срока отложенных ордеров сохранены. Это клиентское OCO: одновременное исполнение двух ордеров при резком движении полностью исключить нельзя.

## Параметры в исходнике

| Параметр | Значение по умолчанию | Смысл |
|---|---:|---|
| `BasePipSize` | 0.01 | Размер одного пипса в единицах цены GOLD, независимо от Digits |
| `BaseInitialSLPips` | 50 | Начальный отступ SL за дальней границей зоны |
| `BaseTrailBars` | 5 | Число закрытых M5-свечей для трала; можно выбрать 3–5 |
| `BaseTrailBufferPips` | 0 | Дополнительный отступ за тенью |
| `BaseHalfExitPips` | 1000 | Расстояние цены от входа до частичной фиксации |

При этих значениях 50 пипс = 0.50 цены, 1000 пипс = 10.00 цены. Например, зона 4100–4110: Buy Stop 4106.50 / SL 4099.50; Sell Stop 4103.50 / SL 4110.50. Если под пипсом имеется в виду 0.10 цены, требуется `BasePipSize=0.10`; это иная ценовая дистанция.

## Сопровождение новых BASE-позиций

BUY: SL за минимальной Low последних N закрытых M5-свечей. SELL: SL за максимальной High. Формирующаяся свеча исключена. SL разрешено только подтягивать, с учётом stops/freeze уровня брокера. Правила перевода в безубыток нет; трал может естественно пройти цену входа. Начальный SL остаётся, если новый кандидат расширял бы риск либо нарушал ограничения брокера.

При движении +1000 пипс (BUY по Bid, SELL по Ask) закрывается 50% исходного объёма, округлённых вниз к шагу лота. Учитываются уже выполненные закрытия из истории позиции. Если половину нельзя закрыть с допустимым остатком, позиция остаётся целиком под тралом: для 0.01 при минимуме/шаге 0.01 частичное закрытие невозможно; для 0.03 закрывается 0.01, остаётся 0.02. Лот не увеличивается ради частичной фиксации.

Перед запросом частичного закрытия сохраняется маркер по стабильному POSITION_IDENTIFIER. Повторные тики и перезапуск не вызывают повторного деления. При однозначном отказе запрос можно повторить через 60 секунд; при таймауте/неопределённом результате маркер остаётся для ручной сверки, трал продолжает работать. При частичном исполнении IOC повторного запроса нет, поэтому фактически закрытый объём может быть меньше запрошенной половины. Фиксированного TP нет; остаток закрывается по SL трала или общей защитой счёта/собственных позиций.

`check_stage1_base.py`: фактические функции геометрии, постановки и проверки ордеров, 8 закрытых свечей, отсутствие зависимости от H1/H4 тейка, native TP=0, OCO по новым комментариям и восстановление из истории, ограничения риска/маржи/неопределённого исполнения.

`check_stage1_regressions.py`: существующие сценарии выполняются против нового исходника: риск/лот/Compression/H4-фильтры, OTE M15, общая экспозиция, бюджет $125/$500 и H4-реконструкция. 13 функций защиты и визуальной геометрии совпадают с исходной базой.

Проверки компилируют извлечённые реальные функции как C++ с имитацией MT5 API. MetaEditor/MT5 в этой среде отсутствуют, поэтому сборка EX5, реальные котировки брокера, отрисовка и прогон GOLD/M5 здесь не проверены.
