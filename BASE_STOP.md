# BASE: Buy Stop / Sell Stop → ближайший экстремум H1/H4

Новый альтернативный режим `BaseUseStopOrders=true`. Старый вход после закрытия за BASE с динамическим 2 ATR TP сохранён при false. Рабочая база — 3.6.5; OTE-сценарий из предыдущей правки сохранён.

## Размещение
Используются прежние численные границы BASE: диапазон 8 свечей со сдвигом 2, ширина < 1.5 закрытого ATR рабочего таймфрейма. Прямоугольники, цвета и подписи сохраняются. Последняя закрытая свеча должна оставаться внутри зоны. На верхнюю границу ставится Buy Stop, на нижнюю — Sell Stop. Ожидать закрытия за зоной больше не нужно.
Триггеры округляются к шагу цены наружу: Buy Stop вверх, Sell Stop вниз. При слишком близкой/уже пройденной границе ордер отклоняется; граница не отодвигается ради прохождения проверки, рыночного догоняющего входа нет. Buy Stop срабатывает по Ask, Sell Stop — по Bid, поэтому учитывается спред.
Каждая сторона проверяется независимо общими H4/D1-фильтрами, данными, cooldown, экспозицией, маржой и OrderCheck. Пара может состоять из одного разрешённого ордера. Никакого нового разрешения против H4 для BASE не добавлено.
Если BaseRequireVolumeSpike=true, для заранее размещаемых заявок проверяется объём последней закрытой свечи подготовки; объём будущего пробоя заранее неизвестен. В новых SET фильтр false.

## SL и TP
SL — за последним подтверждённым локальным минимумом рабочего таймфрейма для BUY и максимумом для SELL, с прежними BaseSwingStrength=2, BaseSwingLookback=64, BaseSLBufferPoints=15. Неизвестный/недопустимый экстремум означает отказ, без выдуманного стопа.
TP — ближайший по цене подтверждённый максимум выше входа для BUY или минимум ниже входа для SELL среди H1 и H4 (`BaseTargetScope=3`). Можно выбрать только H1 (=1) или только H4 (=2). Поиск ограничен последними 64 закрытыми свечами каждого выбранного таймфрейма; используются два закрытых бара с каждой стороны пивота. Будущие свечи и текущие незакрытые H1/H4 не используются. Требуется полнота запрошенного окна истории.
Если цели на выбранных таймфреймах нет или она слишком близка по условиям брокера, соответствующий ордер не ставится. ATR-цель вместо отсутствующего экстремума не подставляется.
SL и TP отправляются вместе с отложенным ордером. Цель фиксируется при размещении; ATR её не переносит. После исполнения сохраняются индивидуальный безубыток по прежним настройкам и глобальная защита. Корзинный фиксированный TP эти позиции не закрывает и не включает их в среднюю цену старой корзины. Старые ATR-позиции продолжают своё прежнее управление.

## Срок, одна пара и OCO
Одновременно обслуживается одна собственная пара BASE Stop на Symbol/Magic. Пока заявка существует, её границы, SL и TP не перестраиваются по новым плавающим окнам накопления.
После входящего исполнения (включая частичное) бот отменяет противоположную сторону и оставшийся объём заявок этой стратегии. Время исполнения сохраняется для cooldown. Диагностический режим не отправляет запросов и не записывает торговое состояние из callback.
Идентификатор зоны записан в комментариях SMC_Base_Stop_B:<time> / SMC_Base_Stop_S:<time>. После перезапуска проверяются открытые позиции и история сделок этой зоны: вторая заявка отменяется даже если первая позиция успела закрыться. Чужие Symbol/Magic и другие модули не отменяются. Отсутствие необходимой истории отменяет ожидающие BASE Stop как непроверяемые.
Срок жизни — BaseMaxWaitBars × длительность рабочего таймфрейма, по умолчанию 10 × M5 = 50 минут. Если брокер поддерживает заданное время экспирации, оно отправляется серверу; иначе срок контролируется на тиках/таймере. Отключение режима/модуля, нарушение общих фильтров или достижение цели без входа также отменяют заявку. При недоступной связи клиентская отмена ждёт восстановления; native SL/TP и серверная экспирация остаются на стороне брокера.
OCO реализован клиентом и не является атомарной серверной парой: на быстром развороте или при разрыве связи обе стороны могут успеть исполниться. Поэтому риск и маржа обеих заявок резервируются вместе, без предположения, что противоположная обязательно отменится. Используется прежний динамический риск каждой сделки, ограниченный прежним общим лимитом. Шкала риска и дополнительное распределение риска между сторонами не менялись.
Если история H1/H4 ещё загружается, подготовка повторяется таймером, без ожидания нового M5. Разрешается постановка новой ожидающей заявки при подключении к уже сформированной зоне только при подходящей текущей котировке; историческая рыночная сделка не воспроизводится.

## Как проверить
Перекомпилировать текущий MQ5. В стартовой строке — `BASE-STOP-1`.
Сначала GOLD/M5, реальные тики, прежняя история/депозит/плечо, `Sniper_v3_6_5_BASE_STOP_ONLY_TEST.set`.
Затем общий прогон с `Sniper_v3_6_5_BASE_STOP_NO_EMA.set` (также включает новый OTE).
Проверить Buy Stop/Sell Stop на границах до пробоя, исходные SL/TP, отмену второй стороны, отсутствие дублей и фиксированную цель H1/H4 после входа. Искать `SN365 BASE STOP`, `SN364 ENTRY`, `SN363 DEAL`, `SN35 SAFETY`. Старый BASE_ONLY_TEST оставляет рыночный ATR-режим.

## Проведённые проверки
check_base_stop_orders.py: фактическая SubmitEntry с типами Buy Stop/Sell Stop, SL/TP, экспирацией, блокировками риска/маржи/OrderCheck/неопределённости и выбором подтверждённых пивотов.
check_base_stop_setup.py: фактическая подготовка BASE, выбор ближайшего H1/H4 и отправка ордеров вместе; независимое разрешение направлений, отсутствие дублей/догоняющего входа, загрузка истории и диагностика.
check_base_stop_oco.py: фактические OnTradeTransaction/ReviewOwnPending/отмена; восстановление по идентификатору зоны, истечение срока, повтор отмены, отсутствие записи в диагностике, изоляция Symbol/Magic.
Сохранены проверки прежних BASE ATR, OTE, компрессии, направления и динамического лота. 13 исходных функций риска/защит/разметки не изменены; EntryPolicy отличается от исходника только применением cooldown к новым BASE Stop.
Эти проверки запускают извлечённый код как C++ с имитацией API MT5. Полная компиляция MQL5 и исторический прогон Strategy Tester в этой среде не выполнены; EX5 не создавался.
