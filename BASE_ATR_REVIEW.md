# Sniper 3.6.5 — BASE ATR working revision

## Реализовано по скриншоту и уточнению пользователя
Торговля от существующей зоны накопления BASE на таймфрейме графика (на скриншоте M5). SELL после закрытия свечи ниже ранее сохранённой нижней границы, BUY после закрытия выше верхней. Касание/тень без закрытия за границей не является сигналом. Котировка при отправке должна оставаться за пробитой границей.

### Почему старая логика могла пропускать вход
Старая версия каждый раз заново требовала узость последних восьми свечей относительно ATR и обязательный всплеск объёма. Нарисованная раньше BASE могла оставаться на графике, хотя её прежние границы больше не использовались для входа. Теперь сначала проверяется сохранённая ранее зона, а не диапазон после импульса. Всплеск объёма — отдельный параметр BaseRequireVolumeSpike=false. Это изменение сигнального фильтра; общие защиты не отключены. Точная причина исторического пропуска без журнала и данных не установлена.

### Жизненный цикл зоны
Исходная детекция BASE (8 свечей, сдвиг 2, диапазон < 1.5 ATR), цвета, подписи и геометрия прямоугольников сохранены. Последняя активная зона хранится численно, без чтения объектов графика. Пока закрытие остаётся внутри неё, новая обнаруженная BASE обновляет рабочие границы. При выходе — одна попытка входа; если фильтры запретили сделку, позднего преследования движения нет. Ожидание ограничено BaseMaxWaitBars=10 свечами после последнего обновления (горизонт исходного прямоугольника). При подключении советника исторический вход не воспроизводится.

### Стоп
Для SELL — выше последнего подтверждённого локального максимума; для BUY — ниже локального минимума. BaseSwingStrength=2: по две закрытые свечи с каждой стороны, без будущих данных; поиск в последних BaseSwingLookback=64 закрытых свечах. Буфер BaseSLBufferPoints=15 пунктов, затем округление по шагу цены в безопасную сторону. При отсутствии подтверждённого экстремума или недопустимом стопе — отказ с записью причины, без подмены стопа границей базы.

### Динамический тейк — подтверждено пользователем
Первоначальный брокерский TP = цена входа ± 2 × ATR. ATR берётся по последней закрытой свече рабочего таймфрейма (M5 при графике M5), с существующим ATR_Period. После каждого нового закрытия TP пересчитывается от фактической цены входа. Он может отдаляться или приближаться при изменении ATR; это не трейлинг-стоп. Если новая цель уже достигнута, отправляется закрытие позиции. При ограничениях stops/freeze или отказе брокера прежний TP сохраняется; причина исполнения видна в журнале, следующая переоценка — на следующем закрытии. Вход, SL и TP проходят OrderCheck вместе; сделка без допустимого первоначального TP не отправляется.
Новые позиции помечены SMC_Base_ATR. Их фиксированный корзинный TP больше не закрывает, и они не участвуют в среднем старой корзины. Безубыток для них рассчитывается индивидуально с прежними Physical_BE_Trigger/Level и сохраняет TP; SL никогда не ослабляется. Старые BASE-позиции с комментарием SMC_Base сохраняют прежнее управление.

## Что сохранено
Шкала динамического и глобального риска, расчёт объёма по денежному риску, H4/D1-фильтры, проверка данных, маржи, экспозиции, дублей, блокировка неопределённого исполнения, собственность Symbol/Magic, глобальный стоп. Соотношение RR фиксированной константой не вводилось; оно следует из локального SL и текущего 2 ATR TP.
Если текущие H4/D1-фильтры запрещают направление, новая база также не торгуется. Это видно по строкам SN35 SAFETY с модулем SMC_Base_ATR. Для самого события пробоя выводится SN365 BASE с границами и направлением; пропуски из-за объёма, экстремума и возврата котировки внутрь имеют отдельные причины. При отсутствии новой закрытой свечи решение не повторяется.

## Предыдущие правки в этой рабочей копии
Компрессия: временный отказ первой попытки не поглощает фазу; повторная оценка максимум раз в 5 модельных секунд, одна успешная сделка на фазу. Исходные ATR-условие, направление и разметка сохранены.
Информационный блок: шрифт 13, справа, ширина 80%, отступ 24 px; перенос вместо уменьшения до 8. Внешний вид в MT5 не проверен.
OTE: заменён на новый сценарий D1 .790 → свип → возврат M15 с ранее сформированным H4 OB. Правила и новые SET — OTE_RECLAIM.md. Старые SET сохранены. Алгоритм 3.6.6 не переносился.

## Файлы и запуск проверки
baseline/ — неизменённые вложения.
Sniper_Manager_v3_6_5_BASE_ATR.mq5 — текущий исходник.
Sniper_v3_6_5_BASE_ATR_NO_EMA.set — прежние настройки плюс новые параметры.
Sniper_v3_6_5_BASE_ONLY_TEST.set — только BASE для изолированной проверки, риск тот же.
baseline/Sniper_v3_6_5_NO_EMA.set — исходное вложение без изменений.

Для проверки в MT5: скопировать рабочий MQ5 в MQL5/Experts, скомпилировать в MetaEditor со стандартными Trade/Trade.mqh и Canvas/Canvas.mqh. В тестере выбрать рабочий советник, GOLD/M5 и тот же участок истории, что на скриншоте; сначала загрузить BASE_ONLY_TEST, затем WORKING_NO_EMA для общей проверки. Сверить SN365 BASE / SN364 ENTRY / SN35 SAFETY, уровни SL/TP, изменение TP после закрытия свечи и отсутствие повторного входа в ту же пробитую базу. Сохранить свежий отчёт и журнал. Автоторговля в наборах включена, как в исходном вложении.

## Проведённые проверки и пределы
python3 tests/check_base_atr.py
python3 tests/check_atr_management.py
Первая команда также запускает прежние проверки компрессии/OTE-предиката/H4/лота. Проверяются реальные извлечённые функции MQL как C++ с имитацией API MT5: сохранённые границы BASE при исчезнувшем новом условии узости, BUY/SELL, подтверждённые экстремумы, исключение теней и повторов, опциональный объём, динамический ATR TP, владение позицией, безубыток, freeze и глобальная блокировка. 14 прежних функций риска/защит/геометрии сравниваются с базой. Все проверки прошли.
Это не компиляция всего советника в MetaEditor и не реальная проверка API брокера/отрисовки/прибыльности. В облачной Linux-среде MT5/MetaEditor/Wine отсутствуют; EX5 не создан, исторический пример из скриншота не воспроизведён.


## Альтернативный Stop-режим BASE
Добавлен отдельно, по умолчанию false для прежних наборов. Buy Stop/Sell Stop, цель у ближайшего подтверждённого H1/H4, SL за локальным экстремумом, OCO и ограниченный срок. Полные правила и новые SET — BASE_STOP.md. Он не заменяет прежний ATR-режим и не меняет OTE.
