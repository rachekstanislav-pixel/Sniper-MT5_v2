# Восстановление предыдущей версии и исправление BASE Stop

Рабочий файл: Sniper_Manager_v3_6_5_RESTORED_STOP_FIX.mq5.
Основа: Sniper_Manager_v3_6_5_BASE_DETECT_2.mq5 из коммита 7d9c819 — до M5_ALL_MODULES_V3. Код V3 и его дополнительный интерфейс не используются в этой сборке; прежние файлы сохранены для истории.

## Что восстановлено
Прежние интерфейс, разметка, логика EMA/Comp/OTE/Sweep/Base/AI; все модули включены. Buy Stop сверху BASE и Sell Stop снизу включены значениями исходника, с отдельным разрешением двух сторон BASE при актуальных данных H4/D1. Стоп за подтверждённым локальным экстремумом, цель — ближайший подтверждённый H1/H4. Сохранены OCO, динамический лот, денежные ограничения, маржа и блокировка неопределённого исполнения. Масштаб риска не менялся. Тест — GOLD/M5, без загрузки старого SET.

## Исправленная общая блокировка
На последнем скриншоте журнал многократно сообщает H4 event fell outside reconstruction window. SF_Update перед пересчётом сбрасывает SF_DataReady; когда сдвигающийся край окна удаляет опорные пивоты, реконструированное последнее событие может стать старее уже подтверждённого. Проверка правильно запрещает откат события, но состояние остаётся not ready, и общий фильтр данных блокирует входы.
Новая версия фиксирует исходную временную границу реконструкции в пределах экземпляра советника. При появлении новых H4-свечей загружается необходимое количество старых закрытых баров, а не отрезается изменяющийся префикс. После загрузки сохранённого события начальная история при необходимости расширяется относительно его времени. Проверки future/changed-anchor/backward-event не отключены; неполная/невалидная история по-прежнему блокирует торговлю. Реконструкция ограничена 5000 свечами; превышение или недоступная история дают явный WAIT. Формат файлов торгового состояния не менялся, стоп-латч/неопределённость/задержки не очищались ради входа.
Это исправляет модель данных, необходимую и для Buy/Sell Stop, и для остальных модулей; интерфейс V3 не переносился.

## Проверки
check_h4_reconstruction.py исполняет реальные функции SF_Update из старого сохранённого файла и новой сборки на одинаковых причинных синтетических H4-свечах (seed 2). Старая версия: ready=334, outside=6. Новая: ready=360, outside=0, changed=0. Подтверждённые события остаются монотонными и не относятся к будущей/открытой свече. Это воспроизведение алгоритмической регрессии, не исторический прогон пользовательского брокера.
Проверены фактическая подготовка двух сторон BASE, типы native pending, SL/TP, сроки, OCO, изоляция Symbol/Magic и чужих модулей, общая экспозиция, OTE, компрессия и управление ATR. 13 прежних функций риска/защит/разметки остались неизменными. Вычисления размера при недостаточном минимальном лоте не обходятся; добавлен только числовой SIZE BLOCK для BASE/OTE.

## Как отличить запуск
Скомпилировать новый файл и выбрать именно RESTORED_STOP_FIX в тестере M5. В начале журнала: SN365 RESTORED_STOP_FIX | base=7d9c819 | previous UI | pinned H4 reconstruction. Не запускать V3/389 вместо него. Минимальный лот/общий риск/маржа всё ещё могут законно отклонить отдельную сделку.
MetaEditor и Strategy Tester здесь недоступны: полная компиляция MQ5 и проверка на реальных тиках ещё требуются. Причина каждой отдельной заявки из последнего скриншота без полного внутреннего журнала не подтверждена.
