# BASE: минимум 0.02, половина +1000, остаток +2000, без безубытка

Файл: `Sniper_Manager_v3_6_5_BASE_HALF_1000_TP_2000.mq5`. Основа — BASE_BOUNDARY_STOP; входы Buy Stop на High / Sell Stop на Low, контртренд, OCO, восьмисвечная зона и правая панель сохранены. Остальные торговые модули выключены.

## Новые правила

| Параметр MQ5 | По умолчанию | Смысл |
|---|---:|---|
| `BaseMinimumLots` | 0.02 | Минимальный заявляемый объём входа |
| `BasePartialPips` | 1000 | Закрыть половину после движения +10.00 цены |
| `BaseFinalPips` | 2000 | TP остатка на +20.00 от фактического входа |
| `BaseBoundaryPipSize` | 0.01 | Один пипс GOLD в единицах цены |
| `BaseBoundarySLPips` | 50 | Начальный SL за дальней границей зоны на 0.50 |

BUY: частичное закрытие по Bid ≥ вход+10.00, TP вход+20.00. SELL: частичное закрытие по Ask ≤ вход−10.00, TP вход−20.00. TP после исполнения корректируется к фактической цене позиции с учётом шага брокера, а не к цене триггера. После этого цель постоянна; ATR её не меняет.

Первоначальный SL остаётся на месте — ни безубытка, ни трала для новых BASE-позиций нет. Общая защита счёта/собственных позиций по риску остаётся действующей и может закрыть позиции до индивидуального SL.

Пример: вход 0.02 BUY по 4110, начальный SL 4099.50. После Bid 4120 закрывается 0.01. Оставшиеся 0.01 имеют TP 4130 и тот же SL 4099.50. Если цена возвращается, остаток может закрыться в убыток; суммарная прибыль позиции не гарантируется.

## Объём и риск

Размер сначала рассчитывается прежней функцией денежного риска, затем ограничивается оставшимся лимитом направления и округляется ВНИЗ так, чтобы половина соответствовала шагу и минимуму брокера. При минимуме/шаге 0.01 доступны 0.02, 0.04, 0.06 и т.д.; расчётные 0.03 становятся 0.02, а не 0.04.

Если риск или лимит позволяет только 0.01, вход пропускается. Минимум 0.02 не является разрешением превышать бюджет. При брокерском минимуме выше 0.01 может потребоваться больший исходный объём, чтобы обе половины были допустимы; если бюджет его не позволяет, входа нет. Пропуск отражается в `BOUNDARY LOT BLOCK` / `SN35 SAFETY`.

Фактическое частичное исполнение брокером может дать объём меньше заявленного. Если разделить его нельзя, недопустимый объём не отправляется; оставшаяся позиция сохраняет первоначальный SL и конечный TP.

## Однократность частичного закрытия

До запроса сохраняется маркер по стабильному POSITION_IDENTIFIER. История учитывает уже закрытый объём; повторный тик/перезапуск не приводит к повторному делению. При однозначном отказе разрешён повтор через 60 секунд; при таймауте/неопределённом результате маркер остаётся для сверки, слепого повтора нет. Если IOC исполнит запрос частично, закрытый объём может быть меньше запрошенного.

Частичное закрытие выполняет работающий советник. При отключённом терминале или скачке сразу через оба уровня серверный TP может закрыть всю позицию раньше частичной операции. SL и конечный TP находятся у брокера после подтверждения запроса.

## Проверки

```sh
python3 tests/check_boundary_partial.py
```

Исполняются реальные извлечённые функции с имитацией MT5 API: минимум 0.02/точное деление/округление вниз, недоступный риск и лимит, BUY по Bid / SELL по Ask, пороги +10/+20 и фактическая цена со слиппеджем, сохранение SL при любой модификации TP, частичное закрытие один раз, восстановление по истории, таймаут, подтверждённый отказ и повтор, недоступная история/диск, диагностика/чужие позиции. Реальная функция постановки зоны проверяется при ATR, отличном от новой фиксированной цели, включая повтор отсутствующей стороны без дублей.

Функции риска/экспозиции, разрешения контртренда и OCO совпадают с предшествующей проверенной сборкой. Исходные правила ATR/BE оставлены только для других старых комментариев/режимов; новые boundary-позиции в этот код не попадают.

Все значения встроены в MQ5. Для теста GOLD/M5 выбрать новое имя `BASE_HALF_1000_TP_2000`, без старого SET. Начальная строка — `SN365 BASE HALF CONFIG`. MetaEditor и MT5 здесь отсутствуют: EX5 и исторический прогон новой сборки не выполнены.
